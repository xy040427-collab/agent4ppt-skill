# 素材使用与证据保真

## 为每张素材指定职责

证据图承载数值、类别、坐标、图例和结论；产品照片承载身份与结构；截图承载操作状态；风格参考承载视觉规则。这些职责不能互换。没有得到重绘要求时，不把一张真实实验结果当作生成“类似图表”的灵感。

在项目旁建立 `assets/figures`、`assets/screenshots` 或其他有意义的目录，把需要长期保留的文件放进去；把来源、提取页码、时间和允许的裁剪方式记入 `sources.md`。这一步由 agent 管理，目前 `init` 只保存路径和哈希，不自动归档素材。

```json
{
  "path": "assets/error-analysis.png",
  "role": "main evidence figure",
  "fidelity": "Keep axes, series, labels, values and legend unchanged; include the whole plot."
}
```

也可以在 `references` 数组中使用一条包含 Markdown 图片的字符串；解析器提取路径和旁边的角色说明。复杂素材优先用对象形式，便于追加保真要求。相对路径以输入 brief 所在目录为基准，单页修订则以项目目录为基准。

## 图像输入闭环

先实际查看每张参考图，判断分辨率、裁剪、语言、轴标签和是否存在敏感信息。内置工具模式按当前工具要求传路径或会话图片；查看文件与向生成工具附图是两个不同动作，不能只做前者。

生成请求应写清第几张是样张、第几张是证据、哪些区域可改。样张只借用视觉系统；真实证据只允许授权的布局处理。多张图需要说明对应关系，例如左图为基线、右图为改进，不让模型猜顺序。

API 模式把所有路径放进 `images`；有图片时走编辑接口。图像数量或格式不受支持时保留任务并报告，不改成纯文本生图。掩膜必须对应第一张输入图；不要把图片裁剪后继续使用尺寸不同的旧掩膜。

## 检查输出

并排检查原图与结果：数据系列数量、极值、符号、单位、图例顺序、截图按钮文案、产品细节、标识形状。数字看不清也是问题，不能因为配色近似就通过。哈希验证仅说明输入文件没有变化，不能证明模型保留了其中的信息。

如果某图必须像素级保持，明确当前整页生成模式无法保证。可以保留原图单独交付或使用用户认可的其他制作方式；不能偷偷切换输出机制，同时继续声称整页由原后端生成。

## 修图与透明素材

局部问题优先使用同一图片后端编辑，只改指定部分并重新检查其他区域；重新生成仍可能改变之前正确的细节。`key` 可处理纯色背景的素材，不用于把错误文字用本地覆盖掩盖。

硬色键适用于干净、明确的背景边缘；软色键适用于抗锯齿边缘，注意透明区和不透明区阈值。边缘内缩会吃掉细线，羽化会降低锐度，去色溢出会改变边缘颜色。主体与背景同色时不能靠增大容差解决；应换背景或采用合适的分割方式。细发丝、玻璃和半透明物体需要单独检查。

## 迁移和交付

跨电脑复制项目时，带上源素材并重新检查路径；数据库含绝对路径，当前没有一键可移植打包命令。交付成品可以只给 PPTX 和预览；保留可修订工程时还应保存数据库、请求、备注和素材。不要把私有照片放进可复用风格库。
