# 演讲备注、质量检查与成品

## 写可直接讲的备注

备注应帮助报告者解释图和推进论证，不是把屏幕上的短句扩写一遍。使用与演示一致的语言，以在场讲述者的视角写。每页可以按“为什么看这张图—先看哪里—证据说明什么—限制是什么—接下来讲什么”组织，内容简单时无需强凑五段。

| 场景 | 备注侧重点 |
|---|---|
| 技术分享 | 术语定义、输入输出、走读顺序、具体例子 |
| 组会或论文 | 实验条件、方法差别、图中证据、限制与待验证假设 |
| 产品说明 | 使用者问题、实际收益、证据及采用条件 |
| 培训 | 操作步骤、常见错误、检查点和练习 |
| 决策汇报 | 判断、依据、风险、选项和所需决定 |

封面与转场只需短说明；普通内容页可以用两到五个短段，中文约 150–400 字作为起点，根据总时长调整。复杂图表需要解释阅读顺序，但如果一页讲稿过长，应检查是否需要拆页。不要把每页都写成“本页主要介绍”。

```markdown
## Slide 1: 本周实验的主要问题

这里首先要说明我们这周试图验证什么。接下来看到的结果，只覆盖本次实验设置，暂时不能外推到全部任务。

## Slide 2: 两种方法的比较

先看横轴对应的测试条件，再比较两条曲线。具体差异以本页真实数据为准；如果样本不足，需要说明这一点。
```

以上示例只演示格式，不能代替实际结果。更新页面后同步修改 `notes.md`，`revise` 不会自动重写讲稿。导出器识别页码标题，将正文写入演讲备注。不要把敏感草稿或内部决策自动加入备注，因为它们会随 PPT 交付。

## 逐页与跨页 QA

逐页看准确文案、中文字符、数字、小数点、单位、来源、图例、图片比例、裁剪和内容遮挡。科学页重点看真实证据，产品页重点看型号与结构，教学页重点看顺序与定义。放大查看文字，再缩到放映尺寸检查是否仍可读。

跨页看用词、颜色含义、阅读节奏、重复构图和结论一致性。并排图应该使用可比较尺度；不同口径不能只因数值好看就排列在同一个比较中。严重内容错误需要重做，不以“整体美观”抵消。

局部修复使用已选图片工具编辑，输出新候选后再验收。需要重新制作时用 `revise` 留下理由。首张样张也是正式页面，同样要参与最终检查。

## 两种组装路径

项目路径：`export PROJECT --out presentation.pptx`。导出器从数据库按页码取已完成图片，核对哈希后写入 PPTX。默认保留 PNG/JPEG 的原始字节；其他图片转换为 PNG。`--max-image-mb` 是单张图片的压缩目标，可能损失细节，不是整个 PPT 的大小上限。

既有图片路径：`assemble --images p1.png p2.png --notes notes.md --ratio 16:9 --out deck.pptx`。参数顺序就是页序，不扫描目录猜测哪些图是成品。它不要求任务数据库，也不声称这些图由本项目生成。支持 16:9 和 4:3，比例不匹配的页面要先检查，避免铺满时产生变形。

## 独立打开与报告

导出后用独立读取器检查页数、尺寸、图片、备注，再尽可能渲染全部页观察。不能用 ZIP 可解压代替 PowerPoint 显示验证；没有桌面版测试时直接说明。CLI 当前不生成 HTML/PDF 预览，由宿主的可用工具另行制作，报告实际采用的方法。

交付说明应包含成品路径、页数、备注情况、实际生成后端、重做页面和剩余限制。用户需要工程时再给项目、素材与请求路径，不把一堆中间文件当成成品。页面文字是栅格内容，不能承诺可单独编辑。自定义视觉系统可以保存到个人库，但仅在用户要求保存后执行，参见 [风格复用](style-library.md)。
