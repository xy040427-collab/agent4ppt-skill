# 提取与保存可复用风格

## 什么时候保存

用户要求以后复用当前 PPT、样张、图片或参考文件的视觉风格时，建立个人配方。一次性的风格参考可以留在当前 brief，不自动扩大成长期个人资料。

先看实际画面。PDF 或 PPT 需要渲染，至少选择能代表封面、正文、证据/流程及收束的页面；短材料有多少看多少。风格发生分段变化时，记录共同规则和具体变体，而不是只提取第一页的背景色。

## 提取字段

| 字段 | 需要记录的内容 |
|---|---|
| `guidance` | 风格识别特征及使用原则 |
| `use` | 合适受众、场合和不适合场景 |
| `canvas` | 背景、边距、密度和比例 |
| `palette` | 主色、辅助色、强调色与语义规则 |
| `typography` | 标题、正文、标签、数字和对齐方式 |
| `page_types` | 封面、章节、正文和结尾的差异 |
| `layouts` | 按内容角色选择的布局名称 |
| `blueprints` | 两到四种以上确有用途的构图及阅读顺序 |
| `imagery` | 照片、截图、图表和插画的不同处理 |
| `elements` | 允许元素与应避免的装饰 |
| `constraints` | 文字、证据、身份标识及密度边界 |
| `review` | 这种风格最容易出现的问题及检查方法 |

这些是配方结构，不是要求从每个参考中硬凑所有效果。保持字段内描述具体、可执行，例如“白底、深蓝标题、红色只强调结论”，比“高端专业”更有用。

## 内容与风格分离

不要把客户名、私人照片、未公开结果、原文段落、机构标识或源文件路径写进配方。风格应当不依赖原始文件也能使用。企业品牌样式只有在用户明确希望复用该身份时才包含相关要求，不能从一次项目参考自动推导出长期品牌授权。

为风格取描述性名称，例如“浅灰精密报告”，避免项目代号、论文名或“我的风格2”。同名覆盖和覆盖内置风格需要明确意图；命令默认拒绝，指定 `--overwrite` 才执行。

## 保存和使用

把提取结果写成 JSON，用 `styles --name 风格名 --save recipe.json` 保存到个人目录的 `styles/风格名.json`。`guidance` 为必需字段，其余结构会原样保留。内置完整配方也通过相同目录查询接口提供，个人同名配方优先。

```text
A4P styles
A4P styles --name 学术汇报
A4P styles --name 浅灰精密报告 --save recipe.json
```

创建下一个 brief 时使用 `"style_name": "浅灰精密报告"`。`init` 会读取并保存配方，后续请求自动携带全部结构；不需要人工复制一段缩略风格描述。无固定名称的临时风格可以直接放在 `style` 或 `style_recipe` 中。

保存后报告名称和实际路径，以及以后如何调用。个人库不随 skill 更新覆盖，但不是自动备份；迁移电脑需要单独复制。配方不会保存 API key，也不要把带凭据的 URLs 写进去。
