# 整页底图与可编辑叠加

## 默认流程：完整成稿 → 局部去除 → 原生拓印

实际制作必须配合 [目标图驱动的原生还原](visual-replication.md)。compose 是初稿；宿主通过 PowerPoint MCP 调整现有文字对象，以 `compose --native-draft` 登记调整结果，再渲染对照、complete。export 保留已验收的文字 XML，不再用最初估算值覆盖。这个入口当前限一张底图加所选文本框；图片叠加与复杂原生对象保留原有路线。仅原生外观调整无需 revise，文案、ID、目标图或底图变化仍须 revise。

新建 `mode: editable` 项目默认 `editable_workflow: full_slide_first`，并强制 `review_policy: structured-v1`。先让图片模型共同设计文字与整页画面；不要预先画文字禁区。`overlays` 初始坐标是暂定值，准确文案、ID 和内容归属先确定。宿主从成稿测量位置、字体、颜色及对齐，试排并提交完整数组；runtime 不自动 OCR，也不能精确识别生图字体。

1. `claim` 返回 `stage: design` 和包含全部文案的成稿提示词。生成完整页面并检查。
2. `record-design --image design.png --overlays-file measured.json --method-file generate.json --qa "实际检查"`：提交从成稿测量的 overlays 数组，保留 IDs、类型、文案和图片素材哈希，仅调整位置与样式。登记后锁定当前修订的成稿与映射；返回去字请求，保存到 `requests/page-NNN-erase.json`。
3. 查看并附加请求中的完整成稿给同一图片工具，执行局部编辑。只移除选定内容，保留图标、容器、圆点、箭头、固定符号及其他画面。边界框是定位提示，不能整块涂白；不承诺逐像素保真。
4. 对照原稿检查去字残留及画面变化；`record-background --image erased.png --method-file edit.json --qa "实际检查"` 登记底图。尺寸须与成稿相同，方法须为 edit。图片与成稿完全相同会被拒绝；不同哈希不等于去字成功，仍需视觉判断。
5. `compose → 宿主渲染 → 对照验收 → complete → export`。只能合成当前修订登记的底图。complete 的方法文件记录去字方法；样张继承完整成稿及其生成方法。

`status.pages[].stage` 显示 design / erase / compose / complete；任务状态仍为 pending / running / complete / failed。租约到期后重新 claim 恢复已登记阶段，须使用新 token。更换成稿、映射或底图必须 revise，旧阶段不进入新修订；可以显式重新登记仍适用的旧文件，注明复用。失败沿用 fail/renew/revise，不直接改数据库。

QA JSON 增加 `design_sha256` 绑定，以及 `erasure_clean`（无残留）、`artwork_preserved`（非编辑画面保留）、`design_alignment`（拓印对位）三项 pass 检查。complete/export 检查成稿、底图、映射、收据、预览和报告的关联与哈希。像素差异统计只作诊断，不是视觉质量评分。

## 兼容路线：预留区域（reserved）

下述先规划留白、再生成无字底图的操作仅用于显式 `editable_workflow: reserved`，或已经初始化且缺少该字段的旧项目。新模板不走该路线。对象边界、内容保真、宿主扩展和通用验收仍适用于两种路线。

## 整页画面与编辑边界

每页仍生成一张构图完整的图，沿用整页生图的设计方法、风格样张和页面任务流程。图中保留场景、立体示意、普通图标、分隔线、箭头、圆点、装饰及不需要修改的内容。只把选定的文字、编号、数据标签或需要替换的图片留给后续原生叠加。不要把这个模式改写成“生成若干素材，再重新拼一页”，也不要将整页底图退化为空白渐变。

先按用户需要划分内容归属。通常标题、正文、图注、步骤编号和需要修改的数据文字属于可编辑层；不要求所有文字都可编辑。固定场景文字、无需修改的图内符号可保留，真实证据图内文字要遵循保真要求。需要保持精确的证据图可作为独立图片叠加。公式用文本叠加时只是可编辑字符，不声称原生公式对象。

例如处理器学习页：CPU/GPU/NPU 的立体方块、流程箭头、编号圆点、矩阵示意、乘号和等号可以一次画入底图；标题、处理器名称、说明、圆点内数字和步骤名称由原生文本补上。若某个图标明确需要替换，底图也留出它的位置，后加独立图片。圆点需保留，只有数字留空。留白应来自完整布局规划，而不是用遮盖块掩住已经画出的字。

## reserved 兼容模式的具体制作步骤

本节的预留区域、先定坐标、无字生图与布局参考规则仅适用于 reserved。full_slide_first 必须按本文开头和 visual-replication.md 执行，不得用本节替代完整成图、模型去字与 MCP 对照还原。两者共享租约和文件验收机制，不共享首次生图提示词。

新制作的 editable 项目使用 `review_policy: structured-v1`；模板已设置此字段。旧项目不自动升级，避免把既有验收追溯为新标准。

有精确图文对位需求时，用 `layout-guide --page-file page.json --out guide.png` 从 overlays 生成诊断参考。它仅画文字安全区，不是成品配图。把返回的 path/role 加入该页 references 后 init/revise，再 claim；不要生成指导图后只放在磁盘而不传给生图工具。先用真实字体试排，导图不会测量字体。`safe_padding` 按页面高度计，默认 0.012；`background_policy: quiet` 禁止前景图形、线条和箭头侵入，`container` 允许简单圆点或面板背景，但内部需清楚。该区域和规则会编入请求。

布局参考是软约束，不保证模型按坐标作画。底图须先检查，合成后须再检查。文字越框检查与原生对象交叠检查都不能检测底图内部的压线。局部合理调位可复用底图；需要明显缩小正文才能容纳时，优先修底图或重新布局。

在 brief 中设置 `mode: editable`。每页 `overlays` 明确原生对象 ID、内容、归一化位置和字体；`raster_text` 列出明确允许生图携带的固定文字。`title` 仅为页主题元数据，需要显示时也放入上述某一层；此模式不再使用含义不明的 `bullets/text`。详见 [brief schema](brief.md)。

1. 规划整页与准确文案，`init`、`prepare` 检查请求；先定文字和图的位置再生图。
2. `claim` 领取整页任务。查看参考图，使用请求里的完整提示词生成一张底图；可编辑内容只提供排版语境，禁止画入底图。普通插画和图标仍随整页生成。沿用 `renew/fail/revise` 和样张机制。
3. `compose PROJECT --page N --token TOKEN --image background.png --out draft.pptx` 用同一规格叠加原生文字和独立图片，返回 `review_file`。此时任务仍为 running。
4. 宿主重新打开并渲染该单页 PPTX，检查真实文字、图文匹配、遮挡、字体和内容归属。需要调整文字位置时，通过 `revise --page-file` 更新规格，重新领取后可复用未受影响的底图，再次 compose。不要假装重新生图。
5. `complete` 仍传原始底图，同时传 `--review-file draft.review.json --preview rendered.png --qa "实际检查结果"`，新项目填写 `--method-file`。只有底图不能登记完成。系统检查当前修订、规格、底图和合成稿哈希，保存合成稿和预览证据；不能机器证明预览确实来自合成稿或替代视觉判断。
6. `export` 验证底图和验收材料后，以同一规格导出整套“底图＋原生对象”。最终 PPTX 仍须重新打开、逐页渲染检查。`--sample` 继承底图的风格及生图方法；协调者同时参考已验收合成页的排版。

页面队列仍只有 pending/running/complete/failed；compose 是 running 内的中间产物，有事件记录，不增加素材级任务调度。图片 API 的 batch 并发和页面队列并发仍分别控制。`assemble` 仍只组装现有整页图片，不能替代本模式的导出。

## 原生图表等扩展

bundled CLI 的可编辑层当前支持原生文本框和独立可替换图片，不支持原生表格、图表、自动连接线或原生公式。明确需要这些对象时，宿主仍可使用自己的制作工具，保留一张完整底图及所选原生对象；保留下文的工作簿、连接线和修改验收要求。这种宿主扩展尚未纳入 `compose/complete/export` 的统一验收，不能伪造 CLI 完成记录。不要把“不支持的对象”静默变成截图，或为了迁移流程删除已有高级能力指导。

以下设计、修改与验收原则用于上述主流程和明确的宿主扩展；独立素材仅用于已划入可编辑层的对象。

目标是保留整页设计的协调感，同时让标题、正文、数字、表格和必要的图示成为可修改对象。场景、光影和复杂装饰可以保留为完整图片；不承诺图片中每个物体都能单独编辑。按宿主已有能力选择制作工具，不要求安装特定库，也不将任务脚本、字体、素材或渲染器加入 skill。

## 整体设计，分别制作

先确定每页准确文案、承担的结论、图文位置与层级，再决定哪些部分由图片表达。统一字体、配色和视觉语言，按内容变化构图。整页背景、自然留白、独立插画都可采用；不要默认将内容变成卡片网格。

把有助于识别内容的图标、标注和连接关系一并规划，不能在可编辑化时只留下正文。普通图标优先选宿主已有的同一套资源，统一线宽、颜色、视觉大小并保留来源；有明确风格需求时再生成定制插画。为每个小图标单独生图可能增加等待和失败次数。用共同对齐、邻近关系和语义颜色组织图文，不把渐变留白当作唯一融合方式。

用真实文字和实际字体试排，留出修改余量。空间不足时调整区域或结构；不能静默删改内容，也不能无限缩小文字。复杂页面可先看布局草稿或视觉样稿，普通页面不必额外生图。样稿用于设计参考，不通过抠字、切碎图片恢复图层。

生图任务应说明整页比例、主体位置及全部视觉结构。full_slide_first 的成稿包含可编辑文案，去字阶段才移除选定内容；reserved 的首次生图才直接省略可编辑文案并预留区域。固定文字按归属清单保留；需要精确保留的图表、截图和标识直接放入页面。保持主视觉完整，避免把一个协调的场景拆成大量独立小图。新增图片使用宿主可用的图片工具。

生成的留白不一定符合指令。先实际观看素材，再检查与文字的配合；文字试排通过不能替代这一检查。遇到景物侵入文字区域，选择修正素材或局部调整布局，不习惯性用大色块遮盖。核对允许的叠放关系，区分设计上的覆盖和错误遮挡。

## 分工与修改

有授权且宿主支持时，协调者统一内容、素材主题、共用元素及设计版本，优先按页领取和派发，独立的叠加素材按需另外分工。执行者拿到固定提示词、参考图用途、输出要求和版本，只生成指定整页底图或明确指定的叠加素材并报告问题，不新增论点、图标体系或页面内容。共享素材只生成一次；并发量按实际后端成功率调整，不承诺按 agent 数量线性加速。

保留对象标识和任务素材。修改时定位已有文字、图表或图片对象；同步修改相关数字、标签和语义颜色，保留未受影响对象。短文本修改通常无需重新生图；内容明显变长时重新检查布局。先支持本工具产生的工程，不声称任意外部 PPT 可无损回写。

活动或步骤改变时，也检查对应图标是否仍然准确。独立图标至少应可替换，不能仅因输入是 SVG 就声称最终文件保留矢量或可拆分路径；检查导出后的资源及兼容预览，必要时使用清晰的透明图片并保留源素材。导入后名称可能丢失，定位修改对象时核对内容、位置和数量，不能猜测对象身份。

## 验收

structured-v1 项目在 complete 时额外提交 `--qa-report report.json`，报告必须绑定 compose receipt 的 page、revision、spec_sha256、image_sha256、draft_sha256，以及实际渲染图的 preview_sha256。填写 reviewer、checks（text_overflow、text_overlap、background_interference、label_alignment、readability）和 issues。五项均 pass、issues 为空才能登记完成；失败报告保留在工作目录，不能把未知项写成 pass。报告归档后，export 验证其哈希。该机制验证证据关联与声明完整性，不能机器证明视觉判断正确，协调者仍须独立看图。

低成本试验先规定页数和生成次数；记录失败首稿与最终稿、每次生图时间、原生文字调整和字号变化。判断是否改善要对照同一页的前后版本。少量案例不证明所有版式成功，也不能用单次工具耗时宣称整体固定加速倍数。

重新打开最终 PPTX，确认正文确实是原生对象，原图、数字和备注完整；渲染并观察每页，核对留白、文字重叠、字体、裁剪和整体观感。程序核对内容与对象，视觉检查判断配合效果，两者不能互相替代。

原生图表还需检查数据文件与引用，尤其是再次导出后。若宿主丢失内嵌工作簿，应保留真实源文件并恢复关联，或换用能完整保存的制作方式；不能用截图或编造数据掩盖。流程箭头应指向正确对象。对比设计质量时保持内容与信息量一致；新增题材样张只能证明该次制作，不能替代与原版的对比。

连接线在预览器与目标软件中可能走不同路径。有目标软件时用其打开并导出核对，不能只看生成工具的预览。自动折线不稳定时，可用明确路径的原生折线保留编辑能力，同时告知其不再自动跟随节点；不要为固定外观把整张图示转成图片。

以可见内容的中心和边缘安排箭头落点，避免指向透明文本框内的空白；多路汇入同一步骤时，可先汇合再用短箭头指向目标。

试验阶段实际修改代表性文字和一项结构化内容，确认未要求变化的素材与对象保持一致。预览应来自最终文件。明确未测试的软件环境，以及仍以图片形式保留的部分。观感是否达到原整页生图基准，应提供对比由用户判断，不能仅凭文件验证通过宣布等价。
