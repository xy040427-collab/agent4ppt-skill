# 大纲、风格和样张

## 先组织表达

阅读输入后先写清楚听众需要理解或决定什么。研究汇报通常需要问题、方法、证据、失败与下一步；产品说明需要用户场景、能力、证据和选择条件。不要把所有内容都硬套成相同的八页目录。

`outline.md` 的每一页应有：页码、标题、页面角色、要表达的结论、准确可见文案、主图、辅助信息和备注方向。通常三个到五个短要点已经足够；公式、代码、图表页可以更少。把“本周进展”这种话题标题具体化为真实结论，但不要把相关性写成因果或把设想写成已完成结果。

记录这页与前一页的关系：提出问题、解释机制、提供证据、比较选项、指出限制或转入行动。页面采用何种构图应由该关系决定，而不是让所有页都变成三张卡片。

## 素材映射

对每张图明确标注“实验证据”“产品外观”“截图”“身份标识”“仅风格”或“仅布局”。大纲中可放实际 Markdown 图片，方便用户观察具体素材，而不只看文件名。示例结构：

```markdown
### 第 4 页：误差集中在小目标
页面角色：结果与失败分析
核心说明：使用真实统计填写结论，未统计时保持为待验证假设。
主图：检测结果；保留框、类别、置信度和原图比例。
![失败样本](assets/failure-case.png)
备注：解释如何选样，不能把挑选的案例代表为全部分布。
```

如果图的用途不明确且会改变结论，先澄清；已获用户授权自行安排时根据材料安排并在交付时说明，不重复要求确认所有常规映射。

## 风格选择与提取

运行 `styles` 读取内置与个人风格。选择时比较背景、强调色、字体层级、图像处理、密度和可接受装饰。不要仅给“科技感”“高级感”等没有可执行含义的标签。用户给出视觉参考时先实际观看；PDF/PPT 需要渲染代表页，文本提取不能代替视觉观察。

通过 `style_name` 选择配方后，`init` 会把完整配方冻结进数据库；以后修改个人风格文件不会偷偷改变已初始化的项目。`style` 可以写本项目追加要求；出现冲突时在初始化前解决，例如不能同时要求“纯黑背景”和“全套白底”。

选取可持续的视觉规则：同类标题保持字号关系、字重、颜色和间距；证据图保持清晰；封面、正文、章节和结尾允许不同的构图。样张只是风格参考，后续不继承样张的旧文案、汽车、机构名称或其他题材。

## 样张如何选

优先选择真实内容页：一张需要保留的图、几句中文、一个有代表性的比较或机制。仅生成空旷封面无法暴露正文密度、文字准确性和证据保真问题。样张仍对应正式页码，不额外增加一页。

在协作模式下展示样张，集中确认字体可读性、图像处理、信息密度和整体气质。直接成品模式下由 agent 检查并记录这个决定。样张不合格先修正提示词或素材；不要一边改样张风格一边让其他页面继续使用旧风格。

验收后用 `complete --sample` 登记；系统会把该图加入后续领取请求。用 `--method-file` 同时记录实际工具、模式、模型及可见参数。隐藏在宿主里的模型版本应写为未暴露，不要猜测。需要参考图的后续页面使用编辑能力时，样张制作也应测试相同路径；确需改变模式则说明原因并建立一致的新执行方案。

如果样张后来被 `revise`，原样张文件仍在。暂停领取其他页，先重新完成样张并再次指定 `--sample`，随后重新领取或修订受影响的任务。已经领取的请求是当时的快照，不会自动替换成新样张。
